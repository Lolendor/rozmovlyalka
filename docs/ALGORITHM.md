# Rozm.exe — реверс-инжиниринг алгоритма синтеза украинской речи

Цель: перенос в Go-библиотеку `rozmovlyalka` (текст → PCM/WAV/MP3).
Источник: `Rozm.exe` (Delphi 7, PE i386, image base 0x400000), «Розмовлялька», А. Чорний, 2003.

Все строки в оригинале — **cp1251 (Windows-1251)**, 1 байт = 1 символ. Порт работает
на байтовых строках cp1251, а не на UTF-8.

## 0. Соответствие VA → файловое смещение

```
CODE (0x401000..0x46ca00):  fo = va - 0x401000 + 0x400
DATA (0x46d000..0x46eb88):  fo = va - 0x46d000 + 0x6be00
```

Delphi `AnsiString`: по адресу `ptr` лежат байты, по `ptr-4` — `int32` длина,
по `ptr-8` — refcount (`-1` = константа).

## 1. Конвейер (главный цикл, FUN_004678b4 / FUN_00468670)

Каждый фрагмент (chunk) проходит конвейер (вызовы 0x467bd9..0x467c76):

```
s := фрагмент + "\r\n"                     ; LStrCat с DAT_00467d30
s := FUN_00465888(s)   ; аббревиатуры / сокращения
s := FUN_004659dc(s)   ; числа → слова (подтверждено вызовами 0x467bfc..0x467c12)
s := FUN_00465e9c(s)   ; английские слова → кириллическая транскрипция
s := FUN_0046621c(s)   ; нормализация (числа, знаки, регистр)
if Length(s) < 2 then пропуск синтеза
else begin
  FUN_00465210(var s)  ; расстановка ударений (in-place)
  s := FUN_0046662c(s) ; G2P: буквы → фонемные коды
  FUN_00466e7c(s)      ; синтез PCM + вывод
end
```

**Чанкование** (главный цикл 0x46791c..0x467c7f, проверено по ассемблеру):

```
acc := ""
for c in text:                        ; 1..N, пропускается хвост за N (0x467c85)
  if c = '\n'        → пропустить символ (в acc НЕ попадает)
  if c = '#'          → взвести флаг команды голоса; continue
  если флаг: c ∈ {'1','2','3'} → сменить голос (DAT_0046e6e8), сбросить флаг, continue
              иначе флаг НЕ сбрасывается (причуда оригинала), символ обрабатывается ниже
  if c = '\r'        → если Length(acc) ≥ 3: озвучить acc, acc := ""
                        иначе аккумулятор сохраняется
  иначе:
      acc += c
      if c = '.' и следующий символ = '.' → continue   ; «..» откладывает границу
      if c ∈ SET_46dff0 → озвучить acc; acc := ""
      else if c — последний символ буфера → озвучить acc; acc := ""
```

То есть фрагменты ограничиваются пунктуацией, `\r` и концом текста;
`\n` отбрасывается полностью, а накопленное перед `\r` короче 3 символов
присоединяется к следующему фрагменту.

## 2. Глобальные настройки (DATA)

| VA          | Смысл                                            |
|-------------|--------------------------------------------------|
| `0x46e6e8`  | выбранный голос: `'1'`,`'2'`,`'3'`               |
| `0x46e6e4`  | скорость (rate), 1..10, норма = 5                |
| `0x46e6e0`  | шаг таблицы дифонов = **42**                     |
| `0x46e710`  | режим: 0 = waveOut (живьём), 1 = запись в файл   |
| `0x46fc5c`  | каталог данных                                   |
| `0x46fca4`  | буфер PCM, 500000 байт, заполняется 0x80         |
| `0x4e9dc4`  | скретч-буфер дифона (0x1b59 байт)                |
| `0x217d27c` | загруженный поток `sd2f` (семплы)                |
| `0x7eabd4`  | загруженный поток `ip2f` — смещения, 1764×int32  |
| `0x7ec764`  | загруженный поток `lp2f` — длины, 1764×int32     |

## 3. Загрузка голоса (FUN_004676c4)

По символу голоса `v ∈ {'1','2','3'}` из каталога данных читаются три файла:

```
<dir>\<v>sd2f  → DAT_0217d27c   (сырые 8-bit unsigned PCM семплы)
<dir>\<v>ip2f  → DAT_007eabd4   (1764 int32: смещение семпла в sd2f)
<dir>\<v>lp2f  → DAT_007ec764   (1764 int32: длина семпла)
```

Индекс дифона: `k = prev * 42 + next`, где `prev`,`next` — фонемные коды 0..41.
`k = 1720` (= 41*42 + 0? нет: 1720 = 40*43… см. ниже) — **пауза в конце**.
1764 = 42*42.

Соответствие потоков в `RozmInstUE1.exe` (RCDATA) извлечённым файлам:
V1 = s12(ip), s13(lp), s14(sd); V2 = s15, s17, s16; V3 = s19, s20, s18.

Фонемный код = `байт - 0xD2`. Диапазон байтов `0xD2..0xFA` → коды `0..40`.

## 7. Соглашение `_LStrCatN` (0x404ccc)

`Dest` в EAX, число аргументов в EDX, сами строки запушены **в порядке конкатенации**:
первый запушенный — первый в результате. Пример:

```
push oldResult      ; arg1
push Chr(x)         ; arg2
push "ъ"            ; arg3
lea  eax, result
mov  edx, 3
call _LStrCatN      ; result := oldResult + Chr(x) + "ъ"
```

# G2P: FUN_0046662c(s) → phoneme string

Подтверждено по ассемблеру 0x46662c..0x466df8. Работает в **два прохода**.

## Дополнительные строковые константы

```
0x466e64 = "й" (0xE9)
0x466e78 = "ш" (0xF8)
```

## Проход 1 (посимвольный, i = 1..Length(s))

Обозначим `c = s[i]`, `n = s[i+1]`, `p = s[i-1]`. Результат накапливается в `r`.

Перед циклом: `if s[1] == '.' then r := r + "ъ"`.

Порядок проверок (ровно как в бинарнике):

1. **Мягкий согласный + `ь`**: `c ∈ SOFTP{д,з,л,н,р,с,т,ц}` и `n == 0xFC('ь')`
   → `r += Chr(soft(c))`, `i += 2`.
   ```
   д→0xD8 з→0xD9 л→0xDA н→0xDB р→0xDC с→0xDD т→0xDE ц→0xDF
   ```

2. **Мягкий согласный + іотированная**: `c ∈ SOFTP` и
   `n ∈ {0xAA Є, 0xB2 І, 0xB3 і, 0xBA є, 0xDE Ю, 0xDF Я, 0xFE ю, 0xFF я}`
   → `r += Chr(soft(c)) + Chr(iot(n))`, `i += 2`, где
   ```
   Ю(DE)→D7  Є(AA)→D3  І(B2)→D5  і(B3)→F9  є(BA)→E5  Я(DF)→D2  ю(FE)→F3  я(FF)→E0
   ```
   (та же таблица soft(c), что в п.1)

3. **Пробел перед гласной**: `c == ' '` и `n ∈ VOWELS(SET_46e030)` и `p ∉ PUNCT(SET_46dff0)`
   → `r += "ъ"`, `i += 1`.

4. **Апостроф**: `c == 0x27` → `i += 1` (пропуск).

5. **Удвоение + іотированная** (вставляется `і` = 0xF9):
   | условие              | результат (`r +=`)     | i   |
   |----------------------|------------------------|-----|
   | `ччя` (F7 F7 FF)     | "ч"+"щ"+"а" = F7 F9 E0 | +3  |
   | `ччю` (F7 F7 FE)     | "ч"+"щ"+"у" = F7 F9 F3 | +3  |
   | `ччі` (F7 F7 B3)     | "ч"+"щ"     = F7 F9    | +3  |
   | `жжя` (E6 E6 FF)     | "ж"+"щ"+"а" = E6 F9 E0 | +3  |
   | `жжі` (E6 E6 B3)     | "ж"+"щ"     = E6 F9    | +3  |

6. **Іотированная гласная**: `c ∈ IOT{Є,Ї,є,ї,Ю,Я,ю,я}`
   → `r += "й" + Chr(iot2(c))`, `i += 1`, где
   ```
   Є(AA)→D3  Ї(AF)→D5  є(BA)→E5  ї(BF)→F9  Ю(DE)→D7  Я(DF)→D2  ю(FE)→F3  я(FF)→E0
   ```

7. **Строчная буква `а..ш`** (`0xE0 <= c <= 0xF8`) → `r += Chr(c)`, `i += 1` (проходит как есть).

8. **Заглавная ударная гласная**: `c ∈ STRESSV{І(B2), і(B3), А(C0), Е(C5), И(C8), О(CE), У(D3)}`
   → `r += Chr(map)`, `i += 1`:
   ```
   А→D2(0)  Е→D3(1)  И→D4(2)  І(B2)→D5(3)  О→D6(4)  У→D7(5)  і(B3)→F9(39)
   ```

9. **`щ` (0xF9)** → `r += "ш" + "ч"` = F8 F7, `i += 1`.

10. **Прочее**: `c ∈ PUNCT` → `r += "ъ"`, `i += 1`; иначе символ **отбрасывается**, `i += 1`.

> Замечание: `local_10` (байт іотированной гласной в п.2) не сбрасывается на каждой
> итерации. Для п.2 триггерное множество совпадает с таблицей, так что «протухших»
> значений не бывает.

## Проход 2 (вставка разделителя между согласными)

```
CONS = SET_46e554 ∪ SET_46e534 ∪ SET_46e514      (SetUnion, 32 байта)
     = {D8 D9 DA DB DC DD DE DF E1 E2 E3 E4 E6 E7 E9 EB EC ED F0 F1 F2 F4 F5 F6 F7 F8}
     (28 байтов = все согласные фонемы: коды 6..13, 15..18, 20, 21, 23, 25..27, 29..32, 34..38)

out := ''
for i := 1 to Length(r):
    if r[i] ∈ CONS and r[i+1] ∈ CONS:  out := out + Chr(r[i]) + "ъ"
    else:                               out := out + Chr(r[i])
out := out + "ъ"
if out[1] != 'ъ':  out := "ъ" + out
```

Итог: строка фонемных байтов `0xD2..0xFA`, всегда начинается и заканчивается на `ъ` (0xFA).

# Синтез: FUN_00466e7c(phonemes)

Подтверждено по ассемблеру 0x466e7c..0x4676ac.

## Буферы

| адрес       | назначение |
|-------------|------------|
| `0x46fca4`  | выходной PCM-буфер `out`, 500000 байт, предзаполнен `0x80` |
| `0x4e9dc4`  | скретч-буфер одного дифона `scratch` (0x1b59 = 6999 байт) |
| `0x4ec0f0`  | `W[0..16]` — float64 веса кроссфейда (BSS, считается при старте) |

## Таблица весов кроссфейда

```pascal
for j := 0 to 16 do
  W[j] := j / 8.0 / 2.0;      // float32 8.0 @0x464634, float32 2.0 @0x464638
```
→ `W[j] = j/16`, W[0]=0, W[16]=1. Хранится как float64.

Константы синтеза: `float32 1.0 @0x4676bc`, `float32 128.0 @0x4676c0`.

## Главный цикл по парам фонем

```
n    := Length(ph)
total:= 0                     // [ebp-0xc]  сколько байт уже в out
XF   := 8                     // [ebp-0x24] половина окна кроссфейда (2*XF+1 = 17)
FillChar(out, 500000, $80)
for i := 1 to n-1 do begin
    prev := ph[i]   - $D2;
    next := ph[i+1] - $D2;

    // --- поправка для голоса 2 ---
    if voice = '2' then
      if (prev in V2SET) and
         (next in {12,13,24,29,32,36,37}) then next := 40;
    // V2SET = {0,1,2,3,4,5,14,19,22,28,33,39}  (все гласные фонемы)

    // --- делитель темпа ---
    if rate < 5 then d := rate
    else if (next < 6) or (prev < 6) then d := 11 - rate
    else d := 12 - rate;

    k    := next + prev*42;                 // DAT_0046e6e0 = 42
    off  := ip2f[k];                        // 0x7eabd4 + 4k
    ulen := lp2f[k];                        // 0x7ec764 + 4k
```

### Извлечение семпла

```
if voice <> '1' then begin                  // голоса 2 и 3
    if ulen <= 0 then continue;
    copy sd2f[off .. off+ulen-1] -> scratch[0..ulen-1];
end else begin                              // голос 1
    if ulen <= 0 then continue;
    hdr := sd2f[off];                       // 1 байт — длина заголовка юнита
    if rate = 5 then begin
        ulen := ulen - hdr;                 // ДЛИНА ПЕРЕЗАПИСЫВАЕТСЯ
        if ulen > 0 then
            copy sd2f[off+hdr .. off+hdr+ulen-1] -> scratch;
    end else
        <сложная пересборка по подуницам, см. «темповая декомпозиция»>;
end;
```

### Склейка в выходной буфер (общий для всех голосов хвост)

```
if total = 0 then begin
    out[0 .. ulen-1] := scratch[0 .. ulen-1];
    total := ulen;
end else begin
    if total + ulen - 2*XF >= 500000 then BREAK;     // буфер полон
    // кроссфейд 17 отсчётов
    for j := 0 to 2*XF do begin                       // 0..16
        a := Round( (1.0 - W[j]) * (int(out[total-2*XF-1+j]) - 128) + 128.0 );
        b := Round( W[j] * (int(scratch[j]) - 128) );
        out[total-2*XF-1+j] := byte(a + b);
    end;
    // остаток нового дифона, кроме последних 17 байт
    m := ulen - 2 - 2*XF;                             // = ulen-18
    if m >= 0 then
        for j := 0 to m do out[total+j] := scratch[2*XF+j];   // scratch[16..ulen-2]
    total := total + ulen - 2*XF - 1;                 // += ulen-17
end;
```

`Round` — **Delphi banker's rounding** (округление к чётному), как `fistp` с
дефолтным управляющим словом FPU. В Go: `math.RoundToEven`.

> Последний байт `scratch[ulen-1]` отбрасывается: копируется `scratch[16..ulen-2]`
> (всего `ulen-17` байт), ровно столько, на сколько сдвигается `total`.

## Вывод

* `DAT_0046e710 = 0` → `waveOutPrepareHeader` / `waveOutWrite` / `WaitForSingleObject(25000)`.
* `DAT_0046e710 = 1` → `TFileStream`: дописывает PCM (или пишет шаблон заголовка 44 байта
  из `DAT_02365704` + PCM), затем патчит размеры:
  * `dword @off 4`  = filesize − 8
  * `dword @off 0x28` = filesize − 8 − 0x24 (= filesize − 44)

## Формат WAV (подтверждено шаблоном `wavhead.bin`)

```
52 49 46 46 | size:LE32 | 57 41 56 45 | 66 6D 74 20 | 10 00 00 00
01 00 | 01 00 | 11 2B 00 00 | 11 2B 00 00 | 01 00 | 08 00 | 64 61 74 61 | dsize:LE32
```
PCM, 1 канал, **11025 Гц**, 11025 байт/с, blockAlign 1, **8 бит без знака**.

## Темповая декомпозиция (голос 1, rate ≠ 5) — 0x46705f..0x4673be

Юнит `sd[off..]` голоса 1 состоит из заголовка и сегментов:
```
sd[off+0] = hdr         (байт; при rate=5 payload целиком лежит по
                        off+hdr длиной lp[k]-hdr и берётся без изменений)
sd[off+1] = segCount    (число сегментов)
sd[off+1+j] = w_j       (смещение записи сегмента от off, j = 1..segCount)
запись сегмента по p = off + w_j (см. ниже)
```

Для каждого сегмента (`w = w_j`):
```
size = LE16(sd[off+w+1], sd[off+w+2])   — смещение куска данных от off
n2   = LE16(sd[off+w+3], sd[off+w+4])   — длина куска
tagType = sd[off+w]
```
Куски сегментов без пропусков и наложений разбивают payload юнита:
`[off+size, off+size+n2) ⊆ [off+hdr, off+lp)`, концы стыкуются впритык и
сумма `n2` по сегментам равна `lp-hdr` (проверено на всех 1764 дифонах).

Буфер вывода — глобальный `scratch` @`0x4e9dc4`; перед декомпозицией все
`0x1B59 = 7001` байт заполняются `0x80` (FillChar), декомпозиция пишет в
него последовательно с позиции `dstPos`. При `rate = 1` раскладка пауз
даёт до ~7347 байт выхода — оригинал честно пишет за границу буфера в
зазор BSS и читает его обратно, поэтому длина выхода не ограничена 0x1B59.

Алгоритм (для каждого сегмента: `srcPos = 0`,
`tmp = sd[off+size .. off+size+n2)` по типу `tagType`):

```
tagType = 1 — «пауза»: записать cnt байт 0x80, где
    cnt = n2 + n2 div d        при rate <= 5
    cnt = n2 - n2 div d        при rate > 5
    (srcPos не меняется — итоговое копирование хвоста вернёт кусок целиком);

tagType = 2 — «растяжение»: period = 70 (35, если prev = 0x20);
    цикл k = 1 .. n2 div period:
        k mod d <> 0            → скопировать period байт из tmp[srcPos..];
                                 srcPos += period
        k mod d = 0, rate > 5   → только srcPos += period (кусок выброшен)
        k mod d = 0, rate <= 5  → скопировать period байт дважды;
                                 srcPos += period

tagType = 3 — «список длин»: lcnt = sd[off+w+5],
    len[m] = sd[off+w+5+m] для m = 1..lcnt;
    если segIdx = 1 → скопировать 8 байт из tmp[0..8);
    цикл k = 1 .. lcnt:
        k mod d <> 0            → скопировать len[k] байт; srcPos += len[k]
        k mod d = 0, rate > 5   → только srcPos += len[k]
        k mod d = 0, rate <= 5  → скопировать len[k] дважды; srcPos += len[k]
```

Итог сегмента: хвост `tmp[srcPos .. n2)` копируется как есть. Для типа 1
`srcPos = 0`, поэтому после вставки паузы всегда идёт весь кусок сегмента.

Делитель `d` (единый для всего юнита, см. «склейка дифонов»):
```
rate < 5                        → d = rate
rate >= 5, prev < 6 или next < 6 → d = 11 - rate
rate >= 5, prev >= 6 и next >= 6 → d = 12 - rate
```

Итоговая длина выхода = накопленный `dstPos`; она присваивается `ulen` и
идёт в общую склейку/кроссфейд. Реализация: `decodeUnitV1` в `synth.go`;
тестовый оракул `testdata/v1_tempo_hash.bin` — длина + FNV-1a 64 декодера
для всех дифонов × всех `rate ≠ 5`, посчитано по ассемблеру независимо.

# Нормализация: FUN_0046621c(s) → res

`procedure(s: AnsiString; var res: AnsiString)` — EAX = `s`, EDX = `@res`.
Подтверждено по ассемблеру 0x46621c..0x466427.

Строковые константы:

0x466470 = "ї"   0x46647c = "є"   0x466488 = " "

Наборы:
```

SET_46dfd0 DIGIT(10): 30..39
```

```
res := ""

for i := 1 to Length(s):
    c := s[i]
    if c in {E0..F9} ∪ {FC} ∪ {FE,FF} then res += Chr(c)                 // строчные укр. буквы (кр. ъ ы э)
    else if c in PUNCT then res += Chr(c)
    else if c == 0x27 (''') then res += Chr(c)
    else if c == 0x5C ('\') then res += Chr(c)
    else if c == 0x60 ('`') then res += "'"
    else if c == ' ' and s[i+1] in DASH then res += ","                   // " -" → ","
    else if c == ' ' and s[i+1] in PUNCT then {пропуск}                    // пробел перед знаком
    else if c in {C0..D9, DC, DE, DF} then res += Chr(c + 0x20)            // А..Я → а..я (Ъ Ы Э НЕ трогаются)
    else if c in {49 'I', 69 'i', B2 'І', B3 'і'} then res += "і"
    else if c in {AF 'Ї', BF 'ї'} then res += "ї"
    else if c in {AA 'Є', BA 'є'} then res += "є"
    else begin                                                             // всё прочее → пробел
        if Length(res) > 0 and res[Length(res)] <> ' ' then res += " "
    end
```

> Важный побочный эффект: `\r\n` в конце строки превращается в `\r` + `" "`,
> потому что `\n` (0x0A) не входит ни в одно из множеств.

# Аббревиатуры: FUN_00465888(s) → res

Подтверждено по ассемблеру 0x465888..0x4659d8.
`procedure(s: AnsiString; var res: AnsiString)` — EAX = `s`, EDX = `@res`.

Проходит по символам `s[1..n-1]` (последний символ `s[n]` дописывается в конце
дословно). Для каждого символа `c = s[i]`:

1. **Буквенные сокращения с точкой.** Линейный поиск `c` в таблице `TBL1`
   (31 байт @ `0x46e070`). Если найден с индексом `j` (1-based) **и**
   `s[i+1] == '.'`, то `res := res + ABBR1[j]` (указатель @ `0x46e08c + 4j`),
   и переход к следующему `i` (точка **не** копируется, `i` увеличивается на 1).
2. **Знаковые сокращения.** Линейный поиск `c` в `TBL2` (6 байт @ `0x46e10c`).
   Если найден с индексом `j`, то `res := res + ABBR2[j]`
   (указатель @ `0x46e110 + 4j`) — **без** требования точки.
3. Иначе `res := res + Chr(c)`.

После цикла: `res := res + Chr(s[n])`. При `n <= 1` цикл не выполняется,
и результат = `Chr(s[n])`. При `n = 0` оригинал обращается к `s[-1]`
(младший байт поля длины = 0) → `Chr(0)`; в Go возвращаем `""`.

# Английская транскрипция: FUN_00465e9c(s) → res

Подтверждено по ассемблеру 0x465e9c..0x466159 и хелперам
0x465afc / 0x465c40 / 0x465cf8.
`procedure(s: AnsiString; var res: AnsiString)` — EAX = `s`, EDX = `@res`.

```
n := Length(s); out := ""; word := ""; tail := ""
inWord := false; nUpper := 0
for i := 1 to n:                              // repeat..until i > n
    c := s[i]
    if 0x41 <= c <= 0x5A then begin isUp := true;  low := c + 0x20 end
    else                            isUp := false
    if 0x61 <= c <= 0x7A then begin isLow := true; low := c end else isLow := false

    if isLow or isUp then begin               // латинская буква
        inWord := true
        word := word + Chr(low)               // ВСЕГДА в нижнем регистре
        if isUp then nUpper++
        continue
    end

    if not inWord then begin                  // не внутри слова — копируем как есть
        out := out + Chr(c)
        continue
    end

    if c == 0x27 (''') then begin             // сокращение типа don't, I'll
        tail := ""; i++
        while 0x61 <= s[i] <= 0x7A: tail := tail + Chr(s[i]); i++
        if tail == "s"  then tail := "с"      // cp1251 F1
        if tail == "t"  then tail := "т"      // F2
        if tail == "m"  then tail := "м"      // EC
        if tail == "d"  then tail := "д"      // E4
        if tail == "ll" then tail := "л"      // EB
        if tail == "re" then tail := "а\"     // E0 5C  → «арэ» с ударением на а
        if tail == "ve" then tail := "в"      // E2
        i--                                   // откат: символ c ещё не обработан
    end

    // --- конец слова ---
    if nUpper > 1 then word := SPELL(word)        // FUN_00465c40: по буквам
    else begin
        w := DICT(word)                           // FUN_00465afc: EUtDic.txt
        if w <> "" then word := w
        else            word := RULES(word)       // FUN_00465cf8: побуквенные правила
    end
    out := out + word + tail + " " + Chr(c)       // LStrCatN, 5 аргументов
    word := ""; tail := ""; inWord := false; nUpper := 0
res := out
```

> Слово, стоящее в самом конце строки (после него нет ни одного нелатинского
> символа), **теряется**: цикл завершается до блока «конец слова».
> В оригинале каждая строка получает суффикс `\r\n`, поэтому на практике
> последнее слово всегда закрывается символом `\r`.

## FUN_00465cf8(word) → res  — побуквенные правила

n := Length(word); res := ""; wantStress := true
i := 1
while i <= n:
    c := word[i]
    t := TBL[c]                            // указатель @ 0x46e328 + 4*c
    if c=='s' and i < n and word[i+1]=='h' then begin
        t := "ш"; i += 2; res := res + t; i++; continue    // без проверки ударения
    end

    if c=='c' and i < n and word[i+1]=='h' then begin

## FUN_00465afc(word) → res  — словарь `EUtDic.txt`

Файл `<data>\EUtDic.txt` (в дистрибутиве — RCDATA-поток `s05`, 1 947 850 байт)
читается построчно в массив `AnsiString` по адресу `0x4ec218` (индексы 1..N),
`N = DAT_005578dc = 105384`. Строки разделены `\r\n`, формат:
`<en-word> <транскрипция>` (транскрипция может содержать маркеры `\`).

```
res := ""
lo := 1; hi := N
while hi - lo > 1:
    mid := (lo + hi) div 2
    rec := ARR[mid]
    key := rec[1..p-1], где p — позиция первого ' ' (или до конца строки)
    if key == word then begin
        res := rec[p+1 .. Length(rec)]     // всё после пробела
        return
    end
    if key <= word then lo := mid else hi := mid
return res                                  // "" = не найдено
```

Файл отсортирован по `key` (проверено: единственная инверсия —
`appropriate`/`approaching` на позиции 3637, на работу не влияет).
Как и в других словарях, записи `ARR[1]` и `ARR[N]` бинарным поиском
**не проверяются** (`a е` и `zzzz зі\з` — служебные границы).

Примеры записей (cp1251 → UTF-8):

```
a е            aaberg а\берг     aachen а\кен       aaker а\акер
aaron е\рен     zywicki зіві\кі   zyskowski зіско\фскі
zzzz зі\з      (первая и последняя записи поиском не проверяются)
```

Файл извлечён в `data/eudic.bin.gz` (1 947 850 байт, 105 384 записи).

## Проверенные причуды оригинала, воспроизведённые в порте

* Кроссфейд дифонов — 17 отсчётов, веса `j/16`, **banker's rounding**
  (`math.RoundToEven`): расхождение с просто округлением ±1 младший бит семпла.
* Хвостовой байт каждого дифона (кроме первого) отбрасывается.
* Токенизатор ударений на конце строки возвращает слово с байтом `0x00`
  (читает за концом AnsiString); в G2P этот байт отбрасывается.
* Темповая декомпозиция голоса `'1'` (0x46705f..0x4673be) портирована
  для всех `rate = 1..10` и проверена побайтово по ассемблерному эталону
  на всех 1764 дифонах × всех темпах. Голоса 2/3 портированы полностью
  (rate влияет только на неиспользуемую ветку декомпозиции).
* Многоформенные записи BSNbn (`'B'..'O'`): форма `r` выбирается при
  предыдущем слове из LIST2 или с окончанием `ої/єї/ого`, иначе форма `q`.
* Правило «`' -'` → `','`» срабатывает и для `%` — так записан битмап
  `SET_46e010` в бинарнике; `%` до нормализации съедается словарём
  аббревиатур (`відсотків`).

## Тесты

`go test ./...` покрывает: таблицу BSNbn, СловКор, EUtDic, известные
ударения (`молокО`, `веснА`, `людИна`, …), многоформенные записи
(`вербИ` после «коло», `вЕрби` без контекста), явный маркер (`словО'чек`),
эталонные фонемные цепочки (`дядько`, `щастя`, `яблуко`), чанкование и
PCM/WAV-выход всех трёх голосов.
